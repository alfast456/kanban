# Product Requirements Document (PRD)
**Project Name:** Personal Kanban Board (Trello Clone)  
**Status:** Draft / Active Development  
**Target Environment:** Localhost & aaPanel (via Docker/Native)  

---

## 1. Ringkasan Eksekutif (Executive Summary)
Proyek ini bertujuan untuk membangun aplikasi manajemen tugas (Kanban Board) berbasis web yang ringan, interaktif, dan berfokus pada fungsionalitas inti *drag-and-drop* seperti Trello. Aplikasi ini dirancang sebagai proyek "ngoding santai" dengan arsitektur yang modular, memungkinkan eksekusi secara lokal (native) dengan transisi mulus menuju kontainerisasi (Docker) untuk deployment ke server aaPanel di masa mendatang.

## 2. Spesifikasi Teknologi (Tech Stack)
* **Frontend:** React.js (dikonfigurasi dengan Vite untuk kompilasi super cepat).
* **Library Drag-and-Drop:** `@hello-pangea/dnd` (menangani logika interaksi UI).
* **Backend:** Node.js dengan framework Express.js.
* **Database:** PostgreSQL (Relasional).
* **Konektor DB:** `pg` (Node-Postgres).
* **Infrastruktur/Deployment:** Native OS execution (Fase 1) & Docker Compose (Fase 2).

## 3. Fungsionalitas Utama (Minimum Viable Product / MVP)
Aplikasi versi awal (MVP) difokuskan pada pemenuhan kebutuhan berikut:
1. **Inisialisasi Papan (Board Initialization):** Aplikasi memuat kolom status secara statis dari database (misal: "To Do", "In Progress", "Done").
2. **Manajemen Kartu (Task Management):** 
   * Pengguna dapat menambahkan kartu/tugas baru ke kolom tertentu.
   * Pengguna dapat menghapus kartu.
3. **Interaktivitas Drag-and-Drop (DND):**
   * **Intra-kolom:** Pengguna dapat mengubah urutan prioritas kartu dalam satu kolom yang sama.
   * **Inter-kolom:** Pengguna dapat memindahkan kartu ke status/kolom yang berbeda.
4. **Persistensi Data:** Setiap perubahan posisi kartu via DND akan langsung mengirim *request* ke backend untuk memperbarui database secara persisten.

## 4. Skema Database
Sistem menggunakan dua tabel relasional utama.

**Tabel `boards` (Kolom/Status)**
| Field | Type | Attributes | Deskripsi |
| :--- | :--- | :--- | :--- |
| `id` | SERIAL | Primary Key | ID unik untuk kolom. |
| `title` | VARCHAR(255) | NOT NULL | Nama kolom (contoh: "To Do"). |
| `position` | INTEGER | NOT NULL | Urutan render kolom dari kiri ke kanan. |

**Tabel `tasks` (Kartu Tugas)**
| Field | Type | Attributes | Deskripsi |
| :--- | :--- | :--- | :--- |
| `id` | SERIAL | Primary Key | ID unik untuk kartu. |
| `board_id`| INTEGER | Foreign Key, Cascades | Referensi ke ID kolom (`boards`). |
| `content` | TEXT | NOT NULL | Teks atau deskripsi tugas. |
| `position`| INTEGER | NOT NULL | Urutan kartu dari atas ke bawah. |

## 5. Spesifikasi API (Backend Endpoints)
Backend mengimplementasikan RESTful API untuk komunikasi data dengan Frontend.

| Method | Endpoint | Fungsi | Payload/Body |
| :--- | :--- | :--- | :--- |
| **GET** | `/api/boards` | Mengambil seluruh daftar kolom beserta urutannya. | - |
| **GET** | `/api/tasks` | Mengambil seluruh kartu tugas yang ada. | - |
| **POST** | `/api/tasks` | Membuat kartu tugas baru. | `{ board_id, content, position }` |
| **PUT** | `/api/tasks/:id` | Memperbarui kolom (`board_id`) dan/atau posisi (`position`) saat DND. | `{ board_id, position }` |
| **DELETE**| `/api/tasks/:id` | Menghapus kartu tugas secara permanen. | - |

## 6. Fase Pengembangan (Milestones)
Pengembangan dibagi menjadi 4 iterasi yang berkesinambungan:

* **Fase 1: Setup Lingkungan & Database (Selesai)**
  - Pembuatan database PostgreSQL (`kanban_db`) dan pembuatan *User*.
  - Eksekusi DDL (Data Definition Language) untuk tabel `boards` dan `tasks`.
* **Fase 2: Pembuatan API Backend (Sedang Berjalan)**
  - Inisialisasi Express.js.
  - Koneksi ke PostgreSQL via `db.js`.
  - Pembuatan endpoint GET, POST, PUT, dan DELETE.
* **Fase 3: Integrasi Frontend & Drag-and-Drop UI**
  - Setup React (Vite).
  - Implementasi *fetching* data dari backend.
  - Integrasi `@hello-pangea/dnd` pada komponen papan tugas.
  - Sinkronisasi event `onDragEnd` dengan endpoint PUT backend.
* **Fase 4: Kontainerisasi (Opsional/Tahap Lanjut)**
  - Penyusunan `Dockerfile` untuk backend dan frontend.
  - Penyusunan `docker-compose.yml`.
  - Uji coba *deployment* lokal dan dokumentasi.

## 7. Syarat Penerimaan (Acceptance Criteria)
Aplikasi dianggap memenuhi spesifikasi MVP apabila:
- [ ] Pengguna dapat melihat kolom dan tugas saat halaman dimuat ulang (*refresh*).
- [ ] Data tugas dan posisi kolom tidak hilang saat server backend di-restart.
- [ ] Memindahkan tugas mengubah statusnya dan posisinya di antarmuka tanpa merusak tata letak.
- [ ] Tidak ada konflik *Cross-Origin Resource Sharing* (CORS) antara Frontend dan Backend saat dijalankan di `localhost`.
